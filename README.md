# CALENDAR

一个极简的日历网站：每天记两条和伴侣之间的小事（TA 对你做的、你对 TA 做的都算），按类型自动生成一枚风格统一的小图标。iPhone 风格，自动适配深色模式，手机和电脑浏览器都能用。

- **前端**：原生 HTML / CSS / JS，无需构建，托管在 GitHub Pages
- **后端**：零依赖，同一份代码既能在本机用 Node 跑，也能部署到 **Cloudflare Workers**（免费、不休眠、不用绑卡）。负责**跨设备同步**、拼稳定风格的 prompt、调用图像 API（密钥不暴露给浏览器）
- **同步**：手机、电脑打开同一个网址、填同一个访问口令，看到的是同一份日历。离线也能记，联网后自动合并
- **日期**：可以补记过去的日子，也可以**提前一天**写明天的；再往后的日期会锁定
- **积攒**：太忙了就点「太忙了，先攒着」，之后在空闲的日子**多写几份来兑现**，欠几份会一直帮你记着

## 太忙了？先攒着，日后兑现

- 某天太忙，没法记两条：点当天的「太忙 · 先攒 N 条」，当天**还空着的位置**会变成"已攒下"（日历格子里显示一个小小的 zzz，每天最多攒 2 条）。
- **待兑现 = 攒下的条数 − 已兑现的条数**，显示在「本月」卡片里。
- 之后在任何一天（含明天），只要还欠着，当天就会多出一个「兑现一条」入口，可以在这天**额外**再记一条（一天最多额外兑现 4 条）。记一条，待兑现就少一条。
- 点一下"已攒下"的位置，可以直接补记，或者「取消积攒」。
- 刚刚攒下的那一天不会出现兑现入口：今天忙到要攒着，当天再去补写说不通。
- 攒下的 💤 不算"已记录"，不会增加"连续记录天数"，也不计入月度统计。
- 这些都只是普通记录，所以和其他数据一样**跨设备同步**，两台设备算出来的"还欠几份"始终一致。

## 跨设备同步是怎么工作的

- 每台设备都有一份**自己的本地副本**（IndexedDB），所以打开就是秒开，断网也能写。
- 改动会标记为"待同步"，联网后推给后端；后端把比你游标更新的内容发回来。启动时、切回标签页时、联网时、每分钟，以及每次修改后都会同步一次。
- 依次修改同一条（同一天同一个位置）：**以最后一次修改为准**。
- 删除会同步给所有设备（后端记一个"删除标记"，而不是真的抹掉）。
- 图标只存一份小图（约 20KB），按「类型 + 文字」去重；新设备会按需把图标下载下来。

### 断线、冲突，都不会丢记录

- **先写本机，再同步**：点保存的那一刻，记录就已经写进本机 IndexedDB（写不进去时也会先留在内存里并提示你导出备份）。断网、后端挂了、图像 API 报错，都不影响记录本身；联网后自动补推。
- **两台设备离线时改了同一个位置**：每次推送都会带上"我是基于哪一版改的"。后端发现你的修改建立在旧版本上、会盖掉别人的不同内容时，**不会覆盖**，而是告诉这台设备"有冲突"。这台设备把自己的那一版**换到同一天下一个空位**（兑现区）保留下来，同时换上后端的版本——两份文字都在，哪份留下由你决定。一天的位置全满时，被换下的文字放进导出备份里的 `overwritten`。
- **存的文字就是你输入的**：全角标点、全角字母、空格之外的字符不会被改写（只合并连续空白）。图标缓存的 key 才会做归一化，所以"ＡＢＣ"和"ABC"共用一张图。
- **图标没出来不影响记录，也不会卡住，也不会弹错误**：连不上图像服务（或被拒绝、超时）时，界面上什么提示都没有，记录继续显示内置的渐变图标，之后会**自动补图**——联网同步后先免费查后端有没有现成的图（`cacheOnly`，不花钱），没有再生成；失败后按 30 秒 / 5 分钟 / 30 分钟退避，最多自动试 3 次，不会反复烧钱。「强制刷新」或在记录里点「重新生成图标」会再试。原因只记在设置里的「最近错误」，不打扰你。
- **「强制刷新 · 清除错误缓存」**（⚙︎ 设置里）：清掉所有失败状态和等待时间，游标归零重新拉一遍后端数据，把没图的记录用已经生成好的图替换，并检查有没有新版本。本机的记录不会因此被删。
- **页面自动更新**：每次部署都会把版本号写进 `config.js`、`version.json` 和所有脚本、样式的网址（`?v=版本号`）。打开着的页面发现版本落后，会自己换到最新版，不再有"浏览器缓存了旧文件、一直报旧错误"的情况。
- 如果后端的数据被清空（比如换了存储），设备发现后会**自动把完整数据重新推回去**，不会丢。
- **访问方式有两种**：①**开放**（`OPEN_ACCESS=true`，本仓库的 Cloudflare 部署就是这样）：不要口令，知道网址的人看到的都是同一份日历，也都能修改；②**口令**：设置 `ACCESS_CODE`。两者都没设置时，后端只回应本机的请求，远程一律 403。
- **开启口令时**，打开网站如果这台设备还没有口令，**第一个出现的是口令窗口**，输对之前后面的内容都用不了。可以勾选「在此设备上记住」，不勾则只在这次浏览器会话里有效。口令在服务器上被改掉后会再次弹出；设置里的「锁定 · 清除本机口令」也会清除本机口令并重新弹出。
- 口令窗口（开启口令时才有）只是登录同步用的，**不是对本机数据加密**：数据在你自己浏览器里，能打开这台设备的人仍然看得到。

### 后端数据存哪

| 场景 | 存储 | 说明 |
| --- | --- | --- |
| 本机运行 `npm start` | 文件（`data/`） | 默认，不用配置 |
| 线上（Cloudflare Workers / Render 等） | **Upstash Redis**（必须） | 免费、持久、纯 HTTP，不用装任何驱动 |

Workers 没有磁盘，Render 免费版的磁盘休眠重启就清空，所以线上**必须**接 Upstash（后端检测到 Render + 文件存储会在设置页和日志里给出警告）。设置只要两分钟：

1. 到 [console.upstash.com](https://console.upstash.com) 新建一个 Redis 数据库（Region 选离你近的，免费版即可）
2. 在数据库页的 **REST API** 一栏复制 `UPSTASH_REDIS_REST_URL` 和 `UPSTASH_REDIS_REST_TOKEN`
3. 把这两个值作为密钥填给线上后端（见下面的部署步骤）

数据量很小：一条记录几百字节，一年约 700 条加几百个 20KB 的图标，远低于免费额度。

## 它是怎么让图标风格稳定的

**画什么，由你写的内容决定**：写"吃大汉堡"就画汉堡，写"下雨天来接我"就画雨伞。**风格和配色是固定的**：[`server/prompt.js`](server/prompt.js) 里的风格段落永远不变，每个类型（言语 / 陪伴 / 礼物 / 照顾 / 拥抱 / 惊喜 / 支持 / 美食 / 酒店 / 回音 / 其他）在 [`frontend/love-types.js`](frontend/love-types.js) 里固定了背景渐变和主色。所以主体各不相同，整套图标放在日历里仍然像同一套。

只有内容里没有具体物件（只有话语、感受，比如"说了句想你了"）时，才会退回到该类型的默认图案（`motif`）。

**「酒店」和「回音」两个类型例外**：它们永远画同一个图案——酒店是两个人抱在一起睡觉，回音是一支笔在写字，不管你写的是酒店名、城市，还是诗的内容（类型里的 `fixedSubject: true`）。同一个类型的所有记录**共用一张图**：只在第一次生成一次，之后再记都直接复用，不再花钱。

### 回音：诗、歌词、长一点的话

- 普通类型一条最多 **60 字**，而「回音」最多 **600 字**，并且**保留换行**（连续的空行只留一个）。
- 文字超过 60 字，或写了三行以上，会自动识别成「回音」。手动选了别的类型又写太长时，保存会提示字数，**不会悄悄截断**你的文字。
- 记录里的「回音」有自己的排版：顶部是小图标和类型标签，下面是衬线体的正文，左边一道细竖线，换行和空行都按你写的样子显示。
- 内部的类型编号仍是 `poem`（已有记录靠它识别），只是显示的名字改成了「回音」。限制和换行规则在 [`frontend/love-types.js`](frontend/love-types.js) 的 `maxLength` / `multiline` / `tidyText` 里，浏览器和后端共用同一份。

输入文字时会按关键词自动识别类型，也可以手动点选。

> 没配置图像 API 或生成失败时，记录不会丢，也不显示错误，先用内置的渐变图标顶着，之后会自动补图；想马上再试，点记录里的「重新生成图标」。
> 改动画风 / 主体规则后，把 `server/prompt.js` 里的 `PROMPT_VERSION` 加 1，旧版本生成的图就不会被当成缓存复用。已经存在的记录不会自动换图，在记录里点「重新生成图标」即可。

## 本地运行

需要 Node 20.12+。

```bash
cp .env.example .env   # 填入 IMAGE_API_KEY
npm start              # http://localhost:3000
```

不填 `IMAGE_API_KEY` 也能跑，只是用内置图标。

### 图像 API 配置

默认走 OpenAI 的 `/v1/images/generations`。任何兼容的服务都行，改 `.env` 即可：

| 变量 | 说明 |
| --- | --- |
| `IMAGE_API_KEY` | 密钥（只放在后端） |
| `IMAGE_API_BASE` | 默认 `https://api.openai.com/v1` |
| `IMAGE_MODEL` | 默认 `gpt-image-2.5-flare`。**不要用 `gpt-image-1`**：OpenAI 已宣布 2026-10-23 下线；`gpt-image-1-mini` 和 `gpt-image-1.5` 在 2026-12-01 下线 |
| `IMAGE_SIZE` | 默认 `1024x1024`；留空则不发送 `size` |
| `IMAGE_PARAMS` | 额外 JSON，合并进请求体，例如 `{"quality":"medium"}`；其他厂商的字段名（如 `image_size`）也在这里设置 |

默认用最低画质（`quality: low`）+ jpeg：图标最终只显示 256px，没必要花更多钱。后端同时兼容 `data[].b64_json`、`data[].url`、`images[].url` 三种返回格式。

## 省钱与花费提醒

按实测，`gpt-image-2.5-flare` 低画质一张图约 **$0.007**（241 个文字 token × $5/M + 196 个图像 token × $30/M），$50 大约够生成 7000 张。

**复用已生成的图，不重复花钱**（三层）：

1. **浏览器端**：同一台设备上，已经有「同类型 + 同文字」的图标，就直接用，连请求都不发。
2. **服务端缓存**：生成出来的原图和浏览器上传的小图都存在持久存储里，按「类型 + 文字 + prompt 版本」查找，空格 / 全半角差异会被归一化。缓存**不含模型名**，将来换模型也能继续复用旧图。
3. **并发去重**：两个相同的请求同时到达，只付一次钱。

只有点「换一张新图标（会消耗额度）」才会绕过缓存。改了 `server/prompt.js` 里的画风想让旧图全部作废时，把 `PROMPT_VERSION` 加 1。

**超过提醒线会警告你**：后端把每次真实调用的花费（按返回的 token 用量精确计算）累加到持久存储里的**原子计数器**（多处同时运行也不会互相覆盖）。累计超过 `BUDGET_WARN_USD`（默认 $50）后，页面顶部会出现红色横幅并弹出提示，设置页的「已花费」一栏也能随时看，后端日志里还会有醒目的 `BUDGET WARNING`。

> **这个账本只统计经过本服务的调用**，不是 OpenAI 账号的总用量。真正的硬上限请在 [OpenAI 后台 Billing → Limits](https://platform.openai.com/settings/organization/billing/limits) 里设置月度预算。

## 部署到 GitHub

GitHub Pages 只能托管静态文件，所以分两部分：**前端放 Pages，后端放一个能跑 JS 的免费服务**。后端有两种选择：

| | Cloudflare Workers（推荐） | Render |
| --- | --- | --- |
| 费用 | 免费，不用绑卡 | 免费，但创建服务时可能要求绑卡验证 |
| 休眠 | 不休眠 | 闲置 15 分钟后休眠，再次访问要等 30–60 秒 |
| 配置文件 | [`wrangler.toml`](wrangler.toml) | [`render.yaml`](render.yaml) |

### 1. 推送到 GitHub

Pages 免费版需要**公开仓库**。`.env` 已在 `.gitignore` 里，密钥不会被提交。

### 2A. 部署后端：Cloudflare Workers（推荐）

1. 注册一个 [Cloudflare](https://dash.cloudflare.com/sign-up) 免费账号。
2. 在项目目录里登录并部署（会在浏览器里授权一次）：
   ```bash
   npx wrangler@4 login
   npx wrangler@4 deploy
   ```
   第一次部署会让你起一个 `workers.dev` 子域名，完成后得到后端地址，形如 `https://love-calendar-api.<你的子域名>.workers.dev`。
3. 设置 3 个密钥（每条命令会提示你粘贴值，粘贴时屏幕不显示是正常的）：
   ```bash
   npx wrangler@4 secret put IMAGE_API_KEY
   npx wrangler@4 secret put UPSTASH_REDIS_REST_URL
   npx wrangler@4 secret put UPSTASH_REDIS_REST_TOKEN
   ```
   默认是**开放访问**（`wrangler.toml` 里 `OPEN_ACCESS = "true"`）：不用口令。想加口令：把它改成 `"false"`，再运行 `npx wrangler@4 secret put ACCESS_CODE` 设一个口令。
4. 验证：`curl https://你的后端地址/api/health`，应该看到 `"store":"upstash"` 和 `"imageConfigured":true`。

**后端固定在美国东部运行**（`wrangler.toml` 里的 `[placement] region = "aws:us-east-1"`），而不是在每个访问者附近运行。原因：OpenAI 不服务某些国家和地区（比如中国大陆、香港、澳门、俄罗斯等），Cloudflare Workers 默认在离访问者最近的机房执行，访问者在这些地方时后端就会在当地机房去调用 OpenAI，被拒绝并报 `Country, region, or territory not supported`。固定地区之后，不管朋友在哪个国家，调用 OpenAI 的位置都是同一个受支持的地区。验证方法：`curl -i https://你的后端地址/api/health`，响应头里有 `cf-placement: remote-IAD` 就说明在美国弗吉尼亚运行。代价是亚洲、欧洲的访问者每次请求会多约 0.3–0.6 秒。

`wrangler.toml` 里已经写好了不涉及密钥的配置（模型、`ALLOWED_ORIGINS` 等）。免费版每个请求最多只能对外发 50 次请求，后端的存储读写已经做了批量化（一次同步 700 条记录只需要 3 次）。

### 2B. 部署后端：Render（备选）

1. Render → New → Blueprint → 选这个仓库（找不到 Blueprint 入口也可以手动建一个 Web Service：Build Command 填 `npm install --omit=dev`，Start Command 填 `npm start`）
2. 填环境变量：`IMAGE_API_KEY`、`ALLOWED_ORIGINS`（你的 Pages 地址，如 `https://<用户名>.github.io`）、`ACCESS_CODE`、`UPSTASH_REDIS_REST_URL`、`UPSTASH_REDIS_REST_TOKEN`
3. 部署完成后得到后端地址，如 `https://love-calendar-api.onrender.com`

### 3. 部署前端（GitHub Pages）

1. 仓库 Settings → Pages → Source 选 **GitHub Actions**
2. 仓库 Settings → Secrets and variables → Actions → **Variables** 新增 `API_BASE` = 后端地址（不带结尾 `/`）
3. 推送到 `main`，[`pages.yml`](.github/workflows/pages.yml) 会自动发布，把 `API_BASE` 和本次构建号写进 `frontend/config.js` / `version.json`，并给脚本、样式的网址加上 `?v=构建号`（只改发布出去的副本，仓库里的文件不动）

打开 Pages 地址就能用（开放模式不要口令；如果后端开了口令，第一次会先弹出口令窗口，每台设备填一次）。

### 4. 装到 iPhone / 安卓主屏幕（像 App 一样点开）

这是一个 PWA：装好后主屏幕上有自己的图标，点开是全屏的，没有地址栏，**断网也能打开**，不用再点链接。

**iPhone：**

1. 用 **Safari** 打开网站地址（别用微信 / 其他 App 里的内置浏览器）
2. 点底部的「分享」按钮 → 往下找到「添加到主屏幕」→ 点「添加」
3. 以后从主屏幕的 CALENDAR 图标进入

**安卓（Chrome）：** 右上角菜单 → 「安装应用」或「添加到主屏幕」。

注意：

- iPhone 上，主屏幕里的 App 和 Safari **各有一份独立的本地存储**。装好后第一次打开会自动从后端把所有记录同步下来，所以装之前先在 Safari 里确认右上角设置显示「已同步」，没有"待同步"的记录就不会丢。
- 好处是：装到主屏幕的 App 不会被 iOS 因为"一周没打开"清掉本地数据（普通网页会）。
- 想让朋友也用：把网址发给 TA，同样的步骤。每个人的主屏幕图标是自己装的，数据都是同一份共享日历。
- 页面更新是自动的：每次打开会联网检查有没有新版本，有就自己换上；断网时用上次存下来的版本。
- 这不是 App Store 里的原生 App。原生 App（.ipa）需要 Apple 开发者账号（每年 $99）才能装到别人的手机上，而且每次更新都要重新签名发版；对这个应用来说，主屏幕版本体验几乎一样，也不用审核。


### 5. 让中国大陆也能连上后端（推荐）

后端在 `*.workers.dev` 上，**中国大陆连不上**（实测 8 个大陆探测点全部超时或被劫持；`*.pages.dev` 也一样）。加上 Netlify 入口后，同样 8 个探测点（电信 / 联通 / 腾讯云 / 阿里云）全部能打开页面，并拿到后端的真实回答。而 `*.netlify.app`、GitHub Pages 本身、Upstash 在大陆都能连上。办法是再开一个 Netlify 入口：它托管同一份前端，并把 `/api/*` 转发给 Cloudflare 上的后端（配置都在 [`netlify.toml`](netlify.toml) 里）。后端本身不动，数据库、生图、固定的美国东部机房都照旧。

1. 打开 [app.netlify.com](https://app.netlify.com)，用 GitHub 账号登录（免费，不用绑卡）
2. **Add new site → Import an existing project → GitHub →** 选这个仓库 → 直接点 **Deploy**（不用改任何设置）
3. 部署完得到一个网址 `https://xxx.netlify.app`，这就是新入口（Site configuration → Change site name 可以改成好记的名字）。本仓库当前的入口是 `https://frabjous-boba-2c325c.netlify.app`；如果打开后一直要求登录 Netlify，是站点被设成了私有，到项目的 Visibility 里把 Production 改成 Public
4. 国内的朋友（和你自己）用这个网址，在设置里点「连接诊断」确认
5. 想让 GitHub Pages 那个网址也自动选能用的：仓库 Settings → Secrets and variables → Actions → Variables，把 `API_BASE` 改成 `https://xxx.netlify.app,https://love-calendar-api.linmz21.workers.dev`（用逗号写多个地址；Netlify 放第一个，因为它在大陆和国外都能连上，workers.dev 在大陆连不上，放前面会白白等到超时）

多个地址是同一个后端的不同入口：请求连不上时会自动换下一个地址重试，之后优先用上次成功的那个，所有地址共用同一个数据库。

注意：

- Netlify 转发请求最多等约 26 秒。同步没问题；生图偶尔会超时，但后端会在后台把图做完存起来，应用稍后自动补图时会免费取到，不会重复花钱。
- 经过 Netlify 的请求在后端看来来自同一个地址，所以按 IP 限流是大家共用一份额度（每分钟 6 次生图、每天 100 次的总上限没变）。
- 手机上每个网址的本地存储是独立的：换到新网址第一次打开会自动从后端同步全部记录；iPhone 想换入口，删掉旧的主屏幕图标，用新网址重新「添加到主屏幕」。

## 访问保护

后端公开在互联网上，里面是日记，生成图片还要花钱。

**开放模式（`OPEN_ACCESS=true`）意味着：知道网址的任何人都能查看、修改、删除这份日历，也能触发图标生成。** 这是有意的选择，下面的限流是仍然有效的保护。如果你不想这样，用口令模式。

- `OPEN_ACCESS`：设为 `true` 时不要口令（即使还留着 `ACCESS_CODE` 也会被忽略）
- `ACCESS_CODE`：口令模式。设置后，没有口令的请求一律 401；**没设置口令也没开放时，后端只回应本机请求**（远程 403）
- `ALLOWED_ORIGINS`：只允许你的 Pages 域名跨域调用
- `RATE_PER_MIN`（默认 6）：每个 IP 每分钟的生成次数
- `DAILY_LIMIT`（默认 200）：每天的生成总量

限流计数放在持久存储里，而不是内存里，所以在 Workers 这种多处同时运行的环境里也准确。

## 图标生成失败时，去哪里看原因

- **这台设备**：⚙︎ 设置里的「最近错误」，写着失败发生的时间、请求到了哪一步、后端返回了什么。
- **连不上后端**：设置里点「连接诊断」，它会逐项测试并给出结论（这台设备能不能连上 Cloudflare、每个后端地址能不能连上、后端看到你在哪个国家），点「复制诊断结果」发给开发者即可。
- **后端**：打开 `<后端地址>/api/health`，`lastFailure` 是最近一次生成失败的原因（只有原因代码、时间、国家和机房，**不含记录内容和 IP**）；账本里还有每种原因的计数（`fail_<原因>`）。`upstream_region` 表示图像服务拒绝了后端当前所在的地区，所以 Worker 用 `[placement]` 固定在美国东部的机房，而不是跟着访问者走。
- 浏览器连不上后端（网络、被墙、广告拦截）和后端拒绝是两回事：前者「最近错误」里会写"无法连接后端"，后者 `lastFailure` 会有记录。两边对不上时，问题就在中间那一段。

## 已知限制

- 这是**共享**日历：所有设备（开放模式下是所有访问者）共用同一份数据，没有多账号。
- 两台设备在**同一个位置**各自改了不同内容：后同步的那份不会覆盖前一份，而是挪到当天下一个空位（带「兑现」标记），需要你自己决定留哪份。没有弹窗提示，在当天的列表里能看到。
- 想给自己留一份备份，可以用 ⚙︎ →「导出备份」，它导出的是 JSON 文件。
- 「清空全部记录」会清空**所有设备**上的数据（包括攒下的）。开放模式下任何访问者都能点它，所以建议偶尔用「导出备份」存一份。
- Cloudflare 免费版每个请求的 CPU 时间有限制（10ms）；日常使用远低于这个量，但生成图标那一次请求处理较大的图片数据，是离上限最近的一处。
